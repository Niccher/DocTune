1. Hardware & Environment Prerequisites

DocTune Studio is designed to run efficiently on both workstation workstations and data center servers. The table below lists tested VRAM allocations using 4-bit QLoRA:

Model Size Minimum VRAM Recommended Hardware Supported Sequence Length
Llama 3 / Mistral (8B) 12 GB - 16 GB NVIDIA RTX 3060/4060, T4, A10G Up to 4,096 tokens
Qwen 2.5 (14B) 18 GB - 24 GB NVIDIA RTX 3090/4090, A5000, L4 Up to 8,192 tokens
Llama 3.1 / Qwen (70B) 48 GB - 80 GB NVIDIA A6000, A100 (80GB), H100 Up to 16,384 tokens
Note: DocTune Studio's hardware governor automatically reads available VRAM and clamps sequence lengths and batch sizes to prevent CUDA OOM panics.

2. 4-Step Quickstart

Follow this standard sequence to train your first specialized domain model:

1
Ingest Documents

Open Document & Data Studio and drag-and-drop your PDF, DOCX, or CSV files. The pre-tokenization scrubber automatically applies PII masking.

2
Synthesize Instruction Dataset

Select your Teacher model (e.g. local Ollama `llama3:70b`) and click Generate QA Pairs. The engine outputs structured train/validation JSONL splits.

3
Train with QLoRA

Navigate to Training Studio. Choose your base model (e.g. `meta-llama/Meta-Llama-3-8B`), set epoch count, and click Start Training. Watch real-time loss telemetry.

4
Evaluate & Export

Test in Evaluation Playground side-by-side with the base model. Once satisfied, visit Checkpoints to fuse weights into a standalone 16-bit model or export an Ollama GGUF.

3. Headless CLI Usage

All pipeline stages can be executed headlessly without the web UI for scheduled batch automation and CI/CD pipelines: 

# 1. Ingest raw documents and generate synthetic QA pairs
python -m pipeline.data_prep --input-dir data/raw_documents --chunk-size 1000

# 2. Launch QLoRA training
python -m pipeline.train --base-model meta-llama/Meta-Llama-3-8B --epochs 3 --batch-size 4 --lr 0.0002

# 3. Fuse LoRA adapter weights with base model
python -m pipeline.merge --adapter-dir checkpoints/qlora --output-dir merged_models/llama3-doctune

# 4. Quantize to GGUF format
python -m pipeline.export_gguf --model-dir merged_models/llama3-doctune --quant-format q4_k_m

4. REST API Reference

DocTune Studio exposes versioned REST API endpoints for seamless programmatic integration:

Method Endpoint Description
GET /api/v1/telemetry Real-time CPU, RAM, GPU VRAM, and checkpoint summary.
POST /api/v1/data-prep/start Starts asynchronous chunking and Teacher QA dataset synthesis.
POST /api/v1/training/start Initiates QLoRA training process with specified hyperparameters.
POST /api/v1/models/merge Fuses LoRA adapter weights into standalone 16-bit safetensors.
POST /api/v1/models/export-gguf Quantizes merged weights to GGUF with automated Modelfile.
POST /api/v1/inference/chat Interactive token streaming endpoint against loaded checkpoints.
GET /metrics Prometheus exposition endpoint for Grafana dashboards.

5. Docker & Production Deployment

Run DocTune Studio inside an isolated NVIDIA container environment: 

# docker-compose.yml snippet
services:
  doctune-studio:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://doctune:secret@postgres:5432/doctune_db
      - S3_ENDPOINT=http://minio:9000
      - S3_ACCESS_KEY=minioadmin
      - S3_SECRET_KEY=minioadmin
      - AUTH_ENABLED=true
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
