DocTune Studio is designed to run efficiently on both workstation workstations and data center servers. The table below lists tested VRAM allocations using 4-bit QLoRA:

2. 4-Step Quickstart

Follow this standard sequence to train your first specialized domain model:

1
Ingest Documents

Open Document & Data Studio and drag-and-drop your PDF, DOCX, or CSV files. The pre-tokenization scrubber automatically applies PII masking.

2
Synthesize Instruction Dataset

Select your Teacher model (e.g. local Ollama `llama3:70b`) and click Generate QA Pairs. The engine outputs structured train/validation JSONL splits.

3
Train with QLoRA

Navigate to Training Studio. Choose your base model (e.g. `meta-llama/Meta-Llama-3-8B`), set epoch count, and click Start Training. Watch real-time loss telemetry.

4
Evaluate & Export

Test in Evaluation Playground side-by-side with the base model. Once satisfied, visit Checkpoints to fuse weights into a standalone 16-bit model or export an Ollama GGUF.

3. Headless CLI Usage

All pipeline stages can be executed headlessly without the web UI for scheduled batch automation and CI/CD pipelines: 

# 1. Ingest raw documents and generate synthetic QA pairs
python -m pipeline.data_prep --input-dir data/raw_documents --chunk-size 1000

# 2. Launch QLoRA training
python -m pipeline.train --base-model meta-llama/Meta-Llama-3-8B --epochs 3 --batch-size 4 --lr 0.0002

# 3. Fuse LoRA adapter weights with base model
python -m pipeline.merge --adapter-dir checkpoints/qlora --output-dir merged_models/llama3-doctune

# 4. Quantize to GGUF format
python -m pipeline.export_gguf --model-dir merged_models/llama3-doctune --quant-format q4_k_m

5. Embedded ChromaDB RAG Subsystem

DocTune Studio incorporates a zero-container embedded RAG architecture. ChromaDB runs entirely in-process using chromadb.PersistentClient backed by SQLite and HNSW on local disk (data/vectorstore/), requiring zero external microservices or open network ports.

Hybrid Retrieval (Dense + BM25)

Combines dense vector cosine similarity (using local BAAI/bge-small-en-v1.5 embeddings) with BM25 keyword matching via Reciprocal Rank Fusion (RRF, $k=60$), ensuring precise technical term and acronym matching.

Verifiable Source Citations

Chunks track SHA-256 hashes, source document filenames, and token byte offsets. Retrieved context is injected into system prompts with bracketed tags ([1], [2]) for interactive citation drawers in the UI.

Programmatic Python Example: Ingest & Query RAG Python Client 
import requests

BASE_URL = "http://localhost:8000"

# 1. Trigger background RAG index creation
res = requests.post(f"{BASE_URL}/api/v1/rag/index/build", json={"project_id": "default"})
print("Index build status:", res.json())

# 2. Query hybrid search directly
query_res = requests.post(
    f"{BASE_URL}/api/v1/rag/query",
    json={"query": "What is the automated failover threshold for Facility B?", "top_k": 3}
)
for chunk in query_res.json().get("chunks", []):
    print(f"[{chunk['score']:.3f}] {chunk['document_name']} -> {chunk['text'][:120]}...")

6. One-Click GGUF & Ollama Exporter

Exporting a trained adapter into a production-ready edge binary previously required multiple manual CLI steps. DocTune Studio automates this end-to-end:

  1. Adapter Weight Resolution: Automatically identifies checkpoint adapter weights (LoRA/QLoRA) and matches them to base causal language models.
  2. Mathematical Fusion: Merges delta weights into standard 16-bit FP16 safetensors with zero runtime PEFT overhead.
  3. GGUF Quantization: Converts weights into compact Q4_K_M, Q5_K_M, or Q8_0 GGUF binaries.
  4. Ollama Modelfile Templating: Inspects model tokenizer configurations to generate exact chat templates (Llama-3, ChatML, Alpaca) and runnable bash scripts.
  5. Hardened Delivery: Securely downloads bundles via /api/v1/models/download-file with strict path-traversal validation.
Deploying Exported Model via Ollama CLI CLI Command 
# Run the one-line Ollama import command generated by DocTune Studio
ollama create my-doctune-model -f ./output_gguf/my-doctune-model/Modelfile

# Start interactive local chat
ollama run my-doctune-model

8. Machine Learning Hyperparameters Guide

Fine-tuning large language models on private enterprise data requires understanding the mathematical dynamics behind parameter-efficient training. The table below details each hyperparameter, its formal definition, its impact on GPU VRAM, and recommended production values.

Hyperparameter Mathematical Definition Practical Function & Trade-Off Recommended Value
LoRA
Low-Rank Adaptation 		W = W₀ + ΔW
ΔW = (α / r) · (B · A)
where B ∈ ℝd×r, A ∈ ℝr×k 		Freezes the billions of parameters in the base model (W₀) and only trains two low-rank bottleneck matrices (A and B). Reduces trainable parameters by >99%, cutting optimizer memory and making consumer GPU training possible. QLoRA (4-bit NF4)
LoRA Rank (r)
Bottleneck Dimension 		rank ≤ r ≪ min(d, k)
Inner dimension of matrices A & B 		Adapter capacity. A higher rank (32, 64) allows the model to learn complex domain facts and terminology, but uses more VRAM. A lower rank (8, 16) regularizes against overfitting on small datasets. r = 16 (Standard)
r = 32 (Complex)
r = 8 (Fast)
LoRA Alpha (α)
Scaling Constant 		Scaling Factor = α / r Update magnitude. Controls how aggressively adapter weight updates alter base activations. Higher α makes the model prioritize newly trained facts; lower α preserves general language abilities. α = 2 × r
e.g. r=16 → α=32
Epochs
Training Iterations 		Total Steps = (N × Epochs) / EffectiveBatch Number of complete passes through the dataset. Too few (<2) leads to underfitting. Too many (>6) causes memorization, hallucinations on rephrased queries, and catastrophic forgetting. 3 - 5 Epochs
Optimal for QA pairs
Learning Rate
Optimizer Step Size (η) 		θ ← θ - η · ∇L(θ) Because only low-rank adapter matrices are trained, LoRA requires a much higher learning rate (2e-4) than Full Fine-Tuning (1e-5). Too high causes loss divergence (NaN); too low stalls convergence. 0.0002 (LoRA/QLoRA)
0.00001 (FFT)
Batch Size
Per-Device Physical Batch 		Samples per forward pass The physical number of samples processed concurrently on the GPU. Primary driver of activation memory. If batch size exceeds GPU capacity, PyTorch triggers a CUDA Out-of-Memory (OOM) panic. 2 - 4 (16GB GPU)
1 (8-12GB GPU)
Grad Accum Steps
Gradient Accumulation 		Effective Batch = BatchSize × AccumSteps Simulates large batches with zero extra VRAM. Accumulates gradients over multiple micro-batches before executing optimizer.step(). Provides stable gradients while fitting into small GPU memory. 4 - 8
Target Effective = 16
Max Sequence Length
Context Ceiling (T_max) 		Attention Memory ∼ Ο(T²) Cutoff token limit for input prompt + expected completion. Attention memory scales quadratically with sequence length: doubling sequence length quadruples attention tensor allocations! 1024 - 2048 tokens
(4096+ needs 24GB+)
Hardware Sizing Rule of Thumb

For 8B parameter models (e.g. Llama 3 8B, Qwen 2.5 7B) using 4-bit QLoRA with sequence length 1024, set Batch Size = 2, Grad Accum = 8 (Effective Batch = 16), Rank = 16, and Alpha = 32. This achieves optimal gradient convergence within 12 GB of VRAM.

Overfitting & Catastrophic Forgetting

To prevent the model from forgetting general knowledge or hallucinating, always maintain a 90/10 train-validation split and monitor evaluation loss. If training loss drops below 0.4 while validation loss rises, stop training immediately.

ALIGNMENT Direct Preference Optimization

9. Human Feedback & DPO Preference Alignment

Supervised Fine-Tuning (SFT) teaches the model domain knowledge, but human preference alignment teaches it which answers to prefer and which to reject. DocTune Studio incorporates Direct Preference Optimization (DPO) to turn human thumbs-up/down ratings into continual alignment data.

The DPO Alignment Loop in DocTune
1
Playground Prompting
Operator asks domain question
2
Human Rating & Correction
Thumbs Up (y_w) vs Down + Fix (y_l)
3
DPO Adapter Training
Direct loss update without PPO
Mathematical Formulation:
L_DPO(π_θ; π_ref) = -E_{(x, y_w, y_l)} [ log σ( β · log(π_θ(y_w|x) / π_ref(y_w|x)) - β · log(π_θ(y_l|x) / π_ref(y_l|x)) ) ]

Where x is the prompt, y_w is the preferred (chosen) answer, y_l is the dispreferred (rejected) answer, π_θ is the model being trained, and π_ref is the frozen reference base model. The hyperparameter β (Beta, default 0.1) controls the strength of the KL divergence penalty against reference drift.

DPO Parameter Recommended Description
Beta (β) 0.1 (Range 0.05 - 0.5) Implicit reward scaling factor. Higher values strictly penalize deviations from the base reference model.
Learning Rate 5e-6 (0.000005) Preference tuning requires a gentle step size to prevent catastrophic destruction of pre-trained reasoning.
Epochs 2 - 3 DPO converges rapidly on high-quality preference datasets (usually 2 to 3 passes).
WORKFLOW Action-by-Action Reference

10. End-to-End Pipeline Actions Reference

A comprehensive breakdown of every action available in DocTune Studio, what happens under the hood, and what assets are generated:

1
Document Ingestion & PII Scrubbing (/data-prep)

Uploads raw documents into raw_documents/. Plain text is extracted, sensitive PII (SSNs, credit cards, emails, tokens) is masked via pii_redactor.py, text is segmented with sliding-window chunking (1000 chars, 200 overlap), and vectors are saved directly into the embedded ChromaDB persistent store (data/vectorstore/).

Output: data/raw_chunks.jsonl & ChromaDB persistent SQLite index
2
Synthetic Instruction Synthesis (/data-prep)

Connects to the configured Teacher LLM (Ollama, vLLM, or API) to synthesize dense QA instruction pairs based strictly on the extracted document chunks. Outputs chat template JSONL format and automatically creates a versioned snapshot in the database.

Output: data/private_docs.jsonl (Train & Val splits)
3
QLoRA / LoRA Training Studio (/training)

Launches background Celery worker or subprocess fine-tuning. Base model weights are loaded in 4-bit NF4, PEFT adapters are attached to attention modules (q_proj, v_proj, ...), and real-time loss telemetry streams via WebSocket to live ApexCharts.

Output: output_qlora/adapter_model.safetensors & adapter_config.json
4
Adapter Weight Merging (/models)

Folds trained low-rank adapter updates back into the base model weights (W = W₀ + ΔW) producing a standalone, unquantized 16-bit float model that can be served directly by vLLM, Hugging Face TGI, or exported to GGUF.

Output: output_merged/ (Complete 16-bit standalone model)
5
1-Click GGUF Quantization & Ollama Modelfile (/models)

Executes llama.cpp quantization into q4_k_m or q8_0 format. Automatically generates an Ollama Modelfile with the correct chat template and system prompt for instant zero-dependency deployment.

Output: output_merged/model.gguf & Modelfile
6
Empirical 4-Way Evaluation & Regression Testing (/experiments)

Tests queries across Base Zero-Shot vs. Base + RAG vs. Fine-Tuned vs. Hybrid (FT + RAG), and executes the 100-sample balanced ARC/MMLU benchmark to quantitatively prove domain adaptation and verify zero regression.

Output: Saved records in PostgreSQL eval_benchmarks table
