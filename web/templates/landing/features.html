TECHNICAL ARCHITECTURE

Deep Dive: The DocTune Studio Pipeline

Explore the complete end-to-end engineering architecture that turns unstructured corporate assets into production-grade specialized models.

STAGE 1

Document Ingestion, Chunking & PII Redaction

DocTune Studio ingests proprietary documents across multiple enterprise formats (PDF, DOCX, CSV, Markdown, TXT). Rather than feeding naive large text chunks into a model, the engine breaks documents into semantically coherent token windows with configurable overlap.

  • Configurable Chunking: Adjustable token chunk sizes (default 1000 tokens) with sliding overlap to preserve context across boundaries.
  • Automated PII Masking: Sensitive identifiers—emails, phone numbers, credit card numbers, and API tokens—are automatically sanitized before dataset assembly.
  • Dual Storage Sync: Documents are persisted to local POSIX disk and optionally mirrored to private MinIO or AWS S3 buckets.

STAGE 2

Teacher LLM Synthetic Q&A Generation

Raw document continuation training often leads to low question-answering accuracy. DocTune Studio uses a high-capacity Teacher LLM (such as local Llama 3 70B, Qwen 2.5 32B via Ollama or custom vLLM) to synthesize high-density instruction-response pairs from your chunks.

  • Multi-Teacher Backend: Connect seamlessly to local Ollama endpoints, local vLLM instances, or private OpenAI-compatible inference servers.
  • Automated JSONL Formatting: Generates structured `instruction`, `input`, and `output` tuples adhering to standard Alpaca and ShareGPT schemas.
  • Train/Validation Split: Automatically partitions generated pairs into training and validation sets for accurate loss tracking.
Configure Teacher Models →

STAGE 3

QLoRA 4-bit Parameter-Efficient Fine-Tuning

Full fine-tuning of 8B or 14B models requires expensive multi-GPU clusters. DocTune Studio utilizes QLoRA with 4-bit NormalFloat (NF4) quantization and double quantization via `bitsandbytes`, making fine-tuning possible on consumer GPUs with as little as 12GB to 16GB of VRAM.

  • Target Module Tuning: Injects low-rank adapters into attention projections (`q_proj`, `k_proj`, `v_proj`, `o_proj`) and MLP layers (`gate_proj`, `up_proj`, `down_proj`).
  • Hardware Governor: Automated boundary detection prevents OOM crashes by clamping batch sizes, max sequence length, and gradient accumulation.
  • Live Telemetry: Real-time streaming loss curves, GPU temperature, VRAM consumption, and step metrics.

STAGE 4

Model Verification, Playground & DPO Curation

Verify your fine-tuned model before releasing it into production. The Evaluation Playground provides interactive streaming chats, side-by-side comparisons against the base model, and alignment feedback collection.

  • Side-by-Side Playground: Run baseline and fine-tuned checkpoints against identical prompts to evaluate domain recall.
  • DPO Dataset Export: Mark responses as "preferred" or "rejected" to generate datasets for Direct Preference Optimization alignment.
  • RAG Benchmark Engine: Benchmark retrieval context answers against ground-truth document chunks.

STAGE 5

Weight Merging, GGUF & Production Deployment

Once satisfied with training quality, fuse low-rank delta matrices directly into base model weights. This produces a standalone 16-bit model requiring no PEFT adapter runtime.

  • Zero-Runtime LoRA Fusion: Mathematically integrates weights: $W = W_0 + \frac{\alpha}{r} (B \times A)$.
  • GGUF Quantization: Converts models to `Q4_K_M`, `Q5_K_M`, and `Q8_0` with automatic Ollama Modelfile generation.
  • Hugging Face Hub Push: Authenticate and export private checkpoints to your organization's Hugging Face repository with one click.
