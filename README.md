# Private Document Fine-Tuning Project

Clean, well-commented pipeline for fine-tuning an 8B-class LLM on your own private documents using three methods:

| Script            | Method          | VRAM (approx) | Best for                          |
|-------------------|-----------------|---------------|-----------------------------------|
| `train_fft.py`    | Full Fine-Tune  | 120–160 GB    | Maximum quality, multi-GPU        |
| `train_lora.py`   | LoRA            | 28–35 GB      | Single high-end GPU               |
| `train_qlora.py`  | QLoRA (4-bit)   | 9–13 GB       | Consumer GPUs (RTX 3090/4090…)    |

---

## Web Studio (AdminLTE v4 + FastAPI)

Launch the interactive dashboard to manage documents, track training loss in real time with ApexCharts, and test evaluation prompts:

```bash
# 1. Install lightweight web requirements
pip install -r requirements-web.txt

# 2. Launch web studio (default port: 4444)
python run_web.py
```
Open **`http://localhost:4444`** in your browser.

## Quick Start (CLI)

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Prepare your documents

Put all PDFs, DOCX and CSV files into `raw_documents/`.

Then run:

```bash
python -m pipeline.prepare_data
```

This will create `data/private_docs.jsonl`.

> **Note**: You need a strong local teacher model (vLLM / Ollama / LM Studio) running at `http://localhost:8000/v1`.  
> Edit the teacher settings in `pipeline/prepare_data.py` or use the Web Studio UI at `http://localhost:4444/data-prep`.

### 3. Train

Choose one of the three methods:

```bash
# Most practical for most people (4-bit QLoRA)
python -m pipeline.train_qlora

# Or pure LoRA (needs ~28-35 GB VRAM)
python -m pipeline.train_lora

# Or full fine-tuning (multi-GPU)
python -m pipeline.train_fft
```

All important hyper-parameters live in `pipeline/common.py` (`Config` class) or can be adjusted via the Web Studio.

### 4. Evaluate

Edit `TEST_CASES` inside `pipeline/evaluate.py` with real questions from your documents, then:

```bash
python -m pipeline.evaluate
```

### 5. Merge adapters into standalone model

```bash
python -m pipeline.merge_adapters
```

The merged standalone model appears in `output_merged/`.

## Recommended Defaults (already set in common.py)

- Model: `meta-llama/Meta-Llama-3-8B-Instruct`
- LoRA rank `r = 16`, alpha `= 32`
- Target modules: all attention + all MLP projections
- Sequence length: 1024
- Epochs: 3

These settings are a solid starting point for most private-document use cases.

## Measuring Success (simple terms)

| What you check              | Good result                                      | Bad result                                      |
|-----------------------------|--------------------------------------------------|-------------------------------------------------|
| Fact Retrieval              | Model states the exact fact from your docs       | Wrong numbers / names or “I don’t know”         |
| Hallucination Resistance    | Model refuses or says information is unavailable | Model invents a plausible-sounding answer       |
| General capability          | Still answers normal coding / math questions     | Suddenly becomes much worse at everyday tasks   |

## Tips

- Always start with **QLoRA** unless you have a clear reason not to.
- Keep a small held-out set of real questions for evaluation.
- For pure factual lookup, consider combining this fine-tune with RAG.
- After training, merge the adapters before deploying to production.
